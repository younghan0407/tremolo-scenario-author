# 산출물 고정 양식 (TC 워크북 `_자동화.xlsx`)

솔루션마다 TC 양식은 다르지만, 산출물은 **원본 워크북 사본 + 하네스가 덧붙이는 고정 부분**으로 같다.
`tremolo.cmd build`(또는 `record --apply`)가 만들고, 이후 실행마다 같은 파일을 누적 갱신한다.

## 원본 열 찾기
TC 시트(`project.json tc.sheet`, 없으면 자동 감지)의 헤더 행(1~10행 자동 감지)에서 열을 **이름으로** 찾는다:
`기능테스트 ID`(필수), `우선순위`, `Depth1~3`, `사전조건`, `테스트 데이터`, `절차`, `예상 결과`, `테스트 결과`(구버전 `실제 결과`), `수행자`, `수행일자`, `비고`.

## TC 시트에 덧붙이는 열 (원본 열 오른쪽 끝, 순서 고정)
| 열 | 내용 |
|---|---|
| `[자동화] 대상` | auto / partial / `제외:<태그>` |
| `[자동화] 스크립트` | 스크립트명 (작성일) — 여러 개면 줄바꿈 |
| `[자동화] 실측 상태` | 실측완료 / 부분실측(n/m) … |
| `[자동화] 최근 결과` | Pass / Fail (판정 대기) / `Fail → <담당자 판정>` / N-T (사유) · 스크립트 갱신 후 미실행 |
| `[자동화] 실행일시` | 최근 결과를 낸 실행 시각 · 런셋 |
| `[자동화] 증적` | 실패 스크린샷 또는 report.html 링크 |

하네스 열 오른쪽에 원본 열이 있으면 빌드를 중단한다(열 순서 보호). 이전 양식 열(`자동화 스크립트`, `자동화`, `포함 스크립트`)은 하네스 열로 보고 다시 그린다.

## 덧붙이는 시트 (TC 시트 바로 뒤, 이름·순서 고정)
| 시트 | 내용 |
|---|---|
| `자동화_요약` | 기준(프로젝트·환경·워크북·하네스 버전), 설계·스크립트·실행 결과 집계, 이 파일 사용 규칙 |
| `자동화_시나리오설계` | 시나리오별 메뉴·우선순위·흐름·TC 수·스크립트 상태·실측·TC 불일치·최근 실행·포함 TC ID |
| `자동화_사전데이터` | 공통 + 시나리오별 실행 전 준비(사전데이터·영향범위 구성, 설정/계정/환경) |
| `자동화_제외TC` | 자동화 제외 TC 와 태그·사유 |
| `자동화_실행이력` | 실행 1회 × 시나리오 1개당 한 행(스텝·TC 집계, 기록/건너뜀 사유, 리포트 링크) |
| `자동화_판정필요` | Fail TC 목록(사전 확인된 TC 불일치 / 신규 실패) + **사람이 쓰는 판정 열(초록 헤더)** |

`build` 는 `deliverables/시나리오_설계.md`(영역별 시나리오 표)도 함께 쓴다.

## 보호 장치
- 원본 열·원본 시트는 수정하지 않는다. 렌더 전/저장 후 **원본 데이터 지문**을 비교해 다르면 저장을 취소한다.
- 저장: `.work/backups` 에 직전 파일 백업(최근 10개) → 임시 파일에 저장·재검증 → 교체.
- 엑셀에서 열려 있으면(파일 잠김 또는 `~$` 잠금 파일) 시작 전에 중단한다.
- `deliverable` 과 `tc.source` 가 같은 파일이면 중단한다(원본 덮어쓰기 방지).
- 사람 칸(판정 열)은 빌드 전에 수확해 `results/verdicts.json` 에 보존한 뒤 다시 그린다. 그 밖의 하네스 영역을 손으로 고친 내용은 다음 빌드에서 사라진다.
