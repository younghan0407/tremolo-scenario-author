# Tremolo 실행 결과 → TC 기록 (record)

Tremolo 에서 런셋을 실행한 뒤, 결과를 **스텝 단위로** TC 에 옮긴다. 사람이 하는 일은 두 가지뿐이다:
`record` 미리보기를 보고 `--apply`, 그리고 Fail 건 판정.

## 절차
```
tremolo.cmd runs                       # 이 프로젝트 시나리오가 들어간 최근 실행 목록(기록 여부 ✓)
tremolo.cmd record latest              # 미리보기 — 아무것도 쓰지 않는다
tremolo.cmd record <Run ID> --apply    # 원장 기록 + 산출물 워크북 갱신
  → 산출물 '자동화_판정필요' 시트에서 Fail 건 판정(초록 헤더 열) → 엑셀 닫고 tremolo.cmd build
```
`<대상>` = `latest` | `runs` 목록 번호 | Run ID | 실행 폴더 경로.

## 입력
`<Tremolo>/result/report/<날짜>/<런셋>/summary.json`(스텝별 `stepNo`·`result`·`error`) + `report-data.json`(시나리오 경로·실행 환경).
스텝 `stepNo` 는 meta 스텝 **순번**(id 아님)이고, TC ID 는 meta 스텝 note 에 있다 → 스텝 결과를 TC 판정으로 옮긴다.
매핑에 쓰는 meta 는 **실행 당시 설치돼 있던 내용**이다: `author install` 이 설치할 때마다 `results/snapshots/` 에 스냅샷과 설치 이력을 남기고,
record 는 실행 시각에 유효했던 스냅샷(없으면 실행 전에 수정된 설치본·생성본)만 후보로 쓴다. TC 범위도 그 meta 의 note 기준이다.

## 판정 규칙 (`scripts/results/ledger.py` 와 동일하게 유지)
| 스텝 결과 | 상태 |
|---|---|
| success | 통과 |
| warning · failed | 실패 |
| pending · running, 또는 첫 실패 이후의 failed, 중지/중단 고정 문구의 failed | 미실행 |

- **TC (한 시나리오 안)**: 그 TC 를 단 스텝 중 실패가 하나라도 → **Fail**, 전부 통과 → **Pass**, 그 외 → **N-T**.
  TC 를 단 스텝이 없으면 시나리오 전체 통과일 때만 Pass, 아니면 N-T('스텝 매핑 없음').
- **TC (한 실행, 여러 시나리오)**: Fail > Pass > N-T (가장 나쁜 쪽).
- **TC 최근 결과**: Pass/Fail 이 나온 가장 최근 실행 기준. 실행된 적 없으면 비움.
- `stamp.mjs mismatch` 로 표기된 스텝(실측 때 TC 와 화면이 다르다고 이미 확인한 스텝)의 Fail 은 **'사전 확인된 TC 불일치'**,
  그 외는 **'신규 실패'** 로 구분해 판정필요 시트에 올린다.

## 가드레일 (차단 = 기록하지 않음)
| 상황 | 동작 |
|---|---|
| 실행이 아직 running | 차단 |
| 실행 환경 URL ≠ 프로젝트 환경(`project.json env`) | 차단 (`--allow-env-mismatch` 로만 허용) |
| 실행 후 스크립트가 수정됨 | **실행 당시 내용**(설치 스냅샷, 또는 실행 전에 수정된 설치본)으로 매핑. 실행 뒤에 바뀐 meta(기대값·TC 연결 변경 포함)는 쓰지 않는다. 당시 내용을 찾을 수 없으면 그 시나리오만 건너뜀 → 현재 스크립트로 다시 실행 |
| registry 에 없는 시나리오 / 다른 솔루션·버전 시나리오 | 건너뜀 / 무시 |
| 산출물 워크북이 엑셀에서 열려 있음(`~$` 잠금 포함) | 차단 — 엑셀을 닫고 다시 |
| 이미 기록된 실행 | 결과 같으면 건너뜀(멱등), 다르면 `--force` 필요 |
| 중지(stopped)·반복 실행 | 경고 표시 후 기록(미실행 스텝 TC 는 N-T) |
| 워크북 저장 실패(디스크·권한 등 모든 오류) | 원장 기록을 되돌림(되돌리기도 실패하면 경로를 표시) |
| 워크북 저장 실패 | 원장 기록을 되돌림(원장 ↔ 워크북 불일치 방지) |

미리보기는 `.work/record/<Run ID>.preview.txt` 에도 남는다.

## 원본과 사람 칸
- 결과의 원본(SoT)은 `results/runs/*.json` 원장이다. 워크북은 원장을 그린 것이라 `build` 로 언제든 다시 그릴 수 있다.
- 자동 판정은 TC 시트 **`[자동화] 최근 결과`** 열에만 쓴다. 원본 `테스트 결과`·`수행자`·`수행일자` 열은 사람이 채운다.
- 사람이 쓰는 칸은 `자동화_판정필요` 시트의 판정·메모·판정자·판정일 열뿐이다. `build` 가 `results/verdicts.json` 으로 수확·보존하고,
  판정이 있으면 TC 시트에 `Fail → <판정>` 으로 표시한다. 판정 선택지: 결함(버그 등록) / TC 수정 필요 / 스크립트 수정 필요 / 환경·데이터 문제 / 정상(Pass 인정).

## AI 가 대신 기록할 때
1. `tremolo.cmd runs` → 대상 실행 확인, `record <대상>` 미리보기를 사용자에게 요약(차단·건너뜀·Fail 목록).
2. 사용자가 확인하면 `--apply`. 차단 사유를 우회하는 플래그(`--allow-env-mismatch`, `--force`)는 사용자가 명시했을 때만.
3. 판정(판정필요 시트)은 사람이 한다 — AI 가 채우지 않는다.
